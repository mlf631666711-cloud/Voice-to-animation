> 每一环都有三样东西：**输入 → 用的工具 → 产物**，以及一条**过关标准**。
> 「大概做完了」不是过关标准。

## ① 输入 · 写稿

**只做一件事**：把你要说的写成人话。

- 一段话讲一件事 —— 这直接决定了后面能切成几镜。
- **不要在稿子里写画面提示**（"这里出现一个图表"）。画面的事归分镜表。
- 数字要用**念法**写（"三百二十毫秒" 而不是 "320ms"），否则 TTS 会念成"三二零毫秒"。

---

## ② 转写 · 拿逐词时间轴

**这是整条管线里最重要的一步。** 后面所有画面的时间点都从这里来。

```bash
# 参考跑法（用你自己的转写工具，只要产出逐词 JSON）
python -c "
from faster_whisper import WhisperModel
m = WhisperModel('medium', device='cpu', compute_type='int8')
segs, info = m.transcribe('voice.wav', word_timestamps=True, language='zh',
                          initial_prompt='<把品牌名、型号、专业术语写在这里>')
...
"
```

**三个关键点**：

1. **档位用 `medium`**。`small` 是早期尝试留下的，专有名词错得离谱。
2. **`initial_prompt` 一定要给真实实体名**（品牌 / 型号 / 人名）。不给，专名必错。
3. **人工校对**。这一步省了，后面全歪 —— 而且歪得很隐蔽（锚点绑到了错词上，画面"看起来"没问题）。

**过关**：`asr.json` 里每个词都有 `start` / `end`，专名全对。

## ③ 判类型 + ③.5 配色

九种类型，各自对应一套背景取向：

| 类型 | 场景 | 背景取向 |
|---|---|---|
| `product` | 产品展示 | 深色 + 产品高光 |
| `launch` | 发布会 | 高对比 + 大面积留白 |
| `tutorial` | 教程 | 浅色 / 中性，可读性优先 |
| `showcase` | 作品展示 | 跟随作品本身色调 |
| `explain` | 讲解 | 低饱和 + 分区色块 |
| `story` | 叙事 | 暖色 / 胶片感 |
| `ui` | 界面演示 | 设备壳色 + 浅底 |
| `data` | 数据 | 深底 + 高饱和强调色 |
| `ink` | 水墨 / 东方 | 纸色 + 墨色 |

```bash
node kit/palette_pick.cjs --type product
```

> **取色的两个输入都随本仓分发**，clone 完直接能跑，不需要额外准备：
> - `palettes/配色灵感集.html` —— 色卡库本体，**159 套配色参考**。它同时是个能双击打开的页面，
>   翻着找灵感、点色块复制 hex 都行。
> - `palettes/data/palettes.json` —— 权重侧车，判「取到的是色卡图还是照片」用。
>
> 想换成自己的色卡库：`PAL_HTML=<你的.html> node kit/palette_pick.cjs --type product`
> （文件里只要有 `palettes = [ {t, tag, desc, colors}, ... ]` 这个数组即可）。

> 为什么不能拍脑袋选：背景色决定了后面所有元素的可读性，也决定了对比度判据能不能过。

## ④ 采素材

两条硬要求：

1. **授权干净**。商用项目只用可商用源。来源不明的图**不要用** —— 出片之后被追责是最贵的错。
2. **文件名不含空格和中文**。渲染时路径要进 URL，空格和中文会带来"找了半天找不到"的 bug。

顺手压一下尺寸（长边 ≤ 2560）。上千张 8K 图会让渲染慢十倍。

### 可选：素材生产班子（不随本仓分发）

采不到素材时，除了接着搜，还有两条路 —— **自己画 SVG**（图表 / 示意 / 图标 / 拓扑：矢量能跟主题走色、
能被动效逐笔驱动、零版权风险）、**走 AI 生成**（实拍质感的场景 / 人物 / 产品氛围）。

本项目在**本地**为这两条路 + 采买 + 动效配方维护了一套**角色卡班子**
（动效师 / 插画师 / 生成师 / 采买，外加需求单模板与验收标准）。
⚠️ **这是可选项，并且不随本仓分发** —— 两个原因：

| 原因 | 说明 |
|---|---|
| **额度消耗大** | 它面向的是「**派一个独立 agent 去干**」的模式：每个岗位都要单独喂 **角色卡 + 需求单 + 验收标准** 三份，上下文成本远高于主 AI 直接做 |
| **依赖本机库存** | 角色卡引用的库存（矢量素材库 / 音效库 / 素材生产管线全文）不在本仓，你 clone 了也跑不起来 |

**什么时候才值得开**：批量素材（十几个图案以上）、或需要反复试错的重活。
**小活（1~3 个图案 / 一两张生成图）**：主 AI 直接做就行 —— 别为了走流程去烧额度。

> **这套做法的核心逻辑，三句话**（不用下载任何东西）：
> ① 素材分三路，按「**先查库存 → 缺结构化图形就画 SVG → 缺实拍质感就走 AI 生成 → 只有实拍影像才上网采**」的顺序走；
> ② 派活时**需求单只写「要什么」，不写「怎么画」**；
> ③ **验收标准提前给**（拿到判据的人才可能一次做对）——**保密的是审核员，不是生产者**。

## ④.5 动效取材 + ⑤ 写分镜表

**先查，别自己想。** 仓库自带：

- **镜头卡 157 张**（`kit/shotcraft/index.json`）—— 每张是一种镜头设计
- **动效术语 558 条**（`kit/shotcraft/terms-index.json`）—— 每条给出可执行参数

```bash
node kit/shotcraft/pick.mjs      # 选镜头
node kit/shotcraft/term.mjs      # 查术语（拿参数，不是形容词）
node kit/check_wording.js        # 校验描述词
```

### 分镜表的六个必填字段

| 字段 | 含义 |
|---|---|
| `cam` | 运镜类型（推 / 拉 / 摇 / 移 / 跟 / 固定…） |
| `cam_amp` | 运镜幅度 |
| `cam_ease` | 运镜缓动 |
| `camkeys` | 关键帧位置 |
| `depth` | 景深 / 层次 |
| `accept` | 该镜的验收要点 |

> **缺任何一个，`new_project.js` 直接报错中止。** 这是故意的 —— 以前手写工程经常漏，
> 漏了之后就是"这一镜的镜头是死的，但没人发现"。

### 词轴锚点

每个元素的入场时间必须绑到**词**：

```js
// ✅ 绑到词轴
{ t: asr[0].words[3].start, ... }

// ❌ 按段边界均分（这是老做法，会导致"话说一半画面就切了"）
{ t: segStart + segDuration * 0.3, ... }
```

## ⑥ 定全局参数

时长、画幅、帧率、全局缓动曲线。时长**必须**从配音实测：

```bash
ffprobe -v error -show_entries format=duration -of csv=p=0 voice.wav
# → 例如 11.03  ⇒ 片子时长 = 12.03
```

## ⑧ 生成骨架

```bash
node kit/new_project.js --spec spec.json --out my_proj [--force] [--mode 3d]
```

产出三个文件：

| 文件 | 作用 |
|---|---|
| `fx_<name>.html` | 工程主文件，开箱带运镜 + 背景 + **每镜 TODO 注释** |
| `_render.js` | 配置 + 调 `renderProject` |
| `_audit.js` | 回归体检（可选） |

- `--force` 不带时，目标已存在**直接报错中止**，绝不覆盖。
- `--mode 3d` 出的是 3D 摄影机骨架（screen → viewport → camera → world 四层）。

**过关**：生成器不报错；浏览器打开 HTML 能看到画面。

## ⑧.5 渲染

```bash
cd my_proj && node _render.js
```

内部链路：**puppeteer 逐帧驱动 Chrome → PNG → ffmpeg 合成**。

- 页面必须实现契约：`window.__frame(t)` 纯函数 + `window.__dur` + `window.__ready`
- **默认输出真 4K**（视口保持设计尺寸 + `deviceScaleFactor=2`）；要 1080p 加 `ss: 1`
- 长片开 `--pipe`（PNG 走 stdin，不落盘）

**过关**：

```
帧数 == 时长 × 帧率          （差一帧都算错）
成片时长 == 配音时长 + 1.0s  （|Δ| ≤ 0.02s）
```

## ⑨ 审判

```bash
node kit/trial.js <工程.html 或 成片.mp4> [--mode fast|standard|deep]
```

**8 条 P0 红线**：

| 红线 | 查什么 |
|---|---|
| `RUNTIME` | 工程跑得起来（`__ready` / `__frame` 契约成立） |
| `PURE` | `__frame(t)` 是纯函数（同一 t 两次结果一致） |
| `MASK` | 起播遮罩已隐藏 |
| `BLANK` | 没有长段空帧 |
| `SAFE` | 安全框内元素没越界 |
| `ZERO` | 零 JS 报错 |
| `OVL` | 没有不该有的重叠 |
| `EDGE` | 元素没跑出画面 |

**退出码 0 = 可交。**

> **只打印 FAIL、不改退出码的工具，不叫门禁。** 它只是个日志。

专项门禁（按需）：

```bash
node kit/layout_check.js     # 版面：四边 / 字幕净空 / 重叠 / 元素数
node kit/boxchk.js           # 安全框（含坐标系自检）
node kit/contrast_check.js   # 对比度（Otsu + WCAG）
node kit/carry_check.js      # 跨镜连续性
```
