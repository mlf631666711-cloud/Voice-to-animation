# 环境与依赖

> 目标：从零到"能出一部片"，**装 4 样东西 + 1 个字体**。
> 装完跑一次 `docs/` 里的自检，全绿就算好。

---

## 一、需要装什么

| 依赖 | 最低版本 | 用来干什么 | 能不能省 |
|---|---|---|---|
| **Node.js** | 18 | 跑所有工具（脚手架 / 渲染 / 门禁） | ❌ 不能省 |
| **Google Chrome** | 任意近期版 | 渲染引擎（逐帧驱动） | ❌ 不能省 |
| **ffmpeg** | 5.0 | 合成、抽帧、度量 | ❌ 不能省 |
| **Python** | 3.11 | 转写 + 图像分析 | ⚠️ 只做画面（已有配音+字轴）可以省 |
| **puppeteer-core** | 21+ | 驱动 Chrome（Node 包） | ❌ 不能省 |
| **中文字体** | —— | 画面上的中文 | ❌ 不能省（且**不随仓库提供**） |

> **为什么用 `puppeteer-core` 而不是 `puppeteer`**：
> `puppeteer` 会额外下载一份 Chromium（几百 MB），而这里直接用**系统 Chrome** —— 更快、更省、版本一致。

## 二、装

> ★ **可以不用一条条敲。** `kit/check_env.js` 自带一个安装器：
>
> ```bash
> node kit/check_env.js --install          # ① 只打印计划：要跑哪几条命令、在哪个目录跑
> node kit/check_env.js --install --yes    # ② 确认了再真装（装完自动重跑一遍自检复验）
> ```
>
> **它管**：`puppeteer-core`（仓库唯一的 Node 依赖）· Chrome / ffmpeg / Python（走 winget / brew）·
> 装完自动复验。
> **它不管**（这几项只给指引，因为替你装的风险大于收益）：**Node.js 本体**（升级运行时是系统级动作）·
> **中文字体**（有版权，且一套几百 MB）· 任何需要 `sudo` 的（非交互环境会卡在密码提示上）。
>
> 另外三条纪律：默认**永不安装**（不带 `--install` 时自检只读不写，行为跟以前一样）·
> 每条命令先把明文打出来再执行 · 只装**必装项**（可选依赖如 Python 包只列出、不动手）。
>
> ⚠️ 装完**当前终端的 PATH 不会刷新** —— 新装的还报 ❌，就**开个新终端**再跑一次自检。
>
> （实现注记：Windows 上它用 `shell` 起 `npm.cmd` —— Node 自 18.20.2 起不许直接 spawn `.cmd`/`.bat`
> （CVE-2024-27980 的修复），不带 shell 会直接 `EINVAL`，而报错完全看不出是这个原因。）

**下面是手动对照表** —— 想自己控制，或遇到上面「不管」的那几项，照它来。

### Windows

```powershell
# Node（选一个）
winget install OpenJS.NodeJS.LTS
# ffmpeg
winget install Gyan.FFmpeg
# Python
winget install Python.Python.3.12
# Chrome
winget install Google.Chrome
```

### macOS

```bash
brew install node ffmpeg python@3.12
brew install --cask google-chrome
```

### Linux

```bash
# Debian / Ubuntu
sudo apt install nodejs npm ffmpeg python3-venv
# Chrome 从官网下 .deb / .rpm
```

### 仓库依赖（只有这一个）

```bash
git clone https://github.com/mlf631666711-cloud/Voice-to-animation.git
cd Voice-to-animation
npm i --no-save --no-package-lock puppeteer-core
```

> ★ **两个 flag 别省**：本仓库**刻意不带 `package.json`**（零构建，全部是单文件脚本）。
> 少了它们，npm 会当场给你造一个 `package.json` + lockfile ⇒ `git status` 立刻变脏，
> 而 README 里刚说过「本仓库没有 `package.json`」。
> （自检脚本的自动安装走的也是这条命令 —— 见 §二 开头。）

### Python 依赖（建议放虚拟环境）

```bash
python -m venv .venv
# Windows
.venv\Scripts\activate
# macOS / Linux
source .venv/bin/activate

pip install faster-whisper numpy Pillow
```

## 三、中文字体（最容易漏的一步）

**仓库不提供字体**（体积 + 授权）。你必须自己装一套。

推荐**开源可商用**的：

| 字体 | 特点 |
|---|---|
| **思源黑体 / Source Han Sans** | 覆盖最全，7 个字重，开源 |
| **阿里巴巴普惠体** | 免费商用，字面现代 |
| **霞鹜文楷 LXGW WenKai** | 楷体风格，适合叙事类 |
| **HarmonyOS Sans** | 现代几何感 |

装法（Windows）：双击 `.ttf` / `.otf` → "为所有用户安装"。
装完**重启浏览器**（字体缓存）。

### ⚠️ 不装字体会怎样

画面上的中文全部变成 **□□□**（方块），而：

- 渲染**正常完成**
- 时长、帧数、分辨率**全部正确**
- 所有自动判据**全绿**

> 这是本管线最典型的"零报错但画面是错的"。**唯一的发现方式是把成片抽一帧出来看。**

## 五、常见安装问题

### 1. `无法解析 puppeteer-core`

`render-core.js` 会按一串候选路径找 `puppeteer-core`，找不到就问你要。

> ★ **这句报错本身就会把下面的 A / B 两条原样印给你** —— `render-core.js` 被 **10 个工具共用**
> （`trial` / `export-engine` / `quad_check` / `layout_check` / `contrast_check` / `carry_check` /
> `motion_fps` / `motion_smooth` / `motion_sweep` …），而且它**在模块顶层就解析依赖**，
> 所以上面任何一个一加载就撞同一句 ⇒ **别的地方看不到「裸」报错**。

四个解法，任选：

```bash
# A. 交给自带的安装器（最省事，推荐）
node kit/check_env.js --install --yes

# B. 只装这一个
npm i --no-save --no-package-lock puppeteer-core

# C. 指到已有的 node_modules
export RENDER_CORE_PUPPETEER=/path/to/node_modules/puppeteer-core
# Windows PowerShell:
$env:RENDER_CORE_PUPPETEER="E:\path\to\node_modules\puppeteer-core"

# D. 全局装
npm i -g puppeteer-core
```

### 2. `找不到 Chrome`

渲染核心按顺序找：环境变量 → 常见安装路径 → `puppeteer.executablePath()` → PATH 上的 `chrome`。

自己指一个：

```bash
export RENDER_CORE_CHROME="C:/Program Files/Google/Chrome/Application/chrome.exe"
```

### 3. `ffmpeg 不是内部或外部命令`

ffmpeg 装了但不在 PATH。两个办法：加进 PATH，或者直接在脚本里写全路径。
（渲染核心同样有候选列表，会把 WinGet 装的路径捞出来。）

### 4. 渲染特别慢

- 4K 每帧 PNG 是 0.2~7.6 MB，**落盘的 syscall 是瓶颈** → 开 `--pipe`（PNG 走 stdin，不落盘）
- 长片可以开并行（`--parallel N`），但注意：**同工程同时刻只跑一个渲染**会覆盖帧（见坑库）
- 只是预览效果的话，先 `ss: 1`（1080p）跑通再上 4K

### 5. 端口 / 进程占住不放

如果脚本崩了留下孤儿 Chrome 进程，下次跑会莫名失败。
Windows：

```powershell
Get-Process chrome -ErrorAction SilentlyContinue | Where-Object { $_.MainWindowTitle -eq '' } | Stop-Process -Force
```

### 6. Python 侧报「缺依赖 numpy / Pillow」

`kit/` 下这几个 Python 工具依赖 `numpy` + `Pillow`：
`content_scan.py`（内容量扫描）· `frame_sheet.py`（接触印）· `motion_probe.py`（运动探测）· `pix.py`（像素统计）。

**它们缺包时会自己打印下面这套命令**，不会甩你一段 `ModuleNotFoundError` traceback：

```bash
# 建议放项目 venv，别污染系统 Python
python -m venv .venv
.venv\Scripts\activate          # macOS / Linux: source .venv/bin/activate
pip install numpy Pillow
```

或者一次把整套环境体检齐（Node / Chrome / ffmpeg / 中文字体 也一起报）：

```bash
node kit/check_env.js
```

> `qc/qc_l1.py` 是**纯标准库**，不依赖任何第三方包 —— 跑 QA 那一步不用装 Python 包。

## 六、目录约定（建议）

```
某个片子/
├── voice.wav          配音（原始，别覆盖）
├── asr.json           逐词时间轴
├── spec.json          分镜表（唯一真源）
├── assets/            素材（命名不含空格/中文）
├── fx_片子.html       工程
├── _render.js         渲染配置
└── out/               产物（不进版本库）
```

> `spec.json` 是**唯一真源**：画面不对改它、重生成骨架，而不是在生成的 HTML 里手改。
> 手改过的 HTML 下次重新生成就丢了 —— 这是新手最常踩的一个坑。
