# 资产库归档 · 六型静默假成功

> ⚠️ **读前须知（先看这段，能省你半小时）**
>
> 本文讲的是**方法论**，**不是一套能直接跑起来的脚本** ——
> 本仓库**不含任何归档脚本、也不含任何库目录**。
> 文中提到的「收齐脚本」「片段清单」，都是**要你自己写的**。
>
> 你从零要做的就三件事（形态见 §1.1）：
> **① 自己新建一个文件夹当库 → ② 在里面维护一份片段清单 → ③ 用 §二 那六道检查去验产物。**
>
> 「六型静默假成功」和「收尾核验清单」跟**具体脚本、具体目录名都无关** —— 它们回答的是
> 「一个由脚本生成的集合体页面，会在哪些地方**零报错地**骗过你」。
> 这一层可以直接搬到任何「素材收集 → 生成索引页 → 交付」的流水线上。
>
> **本文的价值在检查思路，不在命令。**

> **来源**：一条真实生产线上的「资产库归档」实践，2026-09-18 起边做边沉淀；
> 2026-09-23 库从一个 collection 扩成**三个板块**，同时补进两型新的静默假成功（⑤⑥）。
> 文中所有数字都是当轮实测的，不是估算。

## 一、先分清：集合体库里的板块**性质不同**，别混着管

一个长到一定规模的资产库，通常不是一个均质目录，而是**三种性质完全不同的板块**：

| | 板块 | 性质 | 构建方式 | 该怎么验 |
|---|---|---|---|---|
| ① | 自有交付集合体 | **我方**产出的片段集合 | 收齐脚本（**必须幂等**：跑两次产物逐字节相同、且产物**不含**构建时刻） | 多级验收（见 §三 ④） |
| ② | 上游第三方库 | **只读** —— 一个字节都不动 | 人家的脚本 | 人家的判据 |
| ③ | 融合总览 | 上游 + 本库补录 + 自建件，**合在一页看** | 自己的构建脚本（★ 必须有 `--check`） | 全量判据 + 注入自证 |

**为什么必须先分清**：三者的「可动范围」完全不同。
把上游板块当自有板块改（或反过来）是这类库里最容易出的第一类事故 ——
而它**不会报错**，只会在下一次同步上游时把改动静静吞掉。

> ★ 推论：**「删掉上游某张卡」的正确做法 = 写进一份 `deleted.json`，由构建期过滤** ——
> **不许删上游文件**。删文件当下看不出问题，下次同步就回来了（或者更糟：冲突）。

### 1.1 起手：目录**你自己建**（本仓库不含任何库目录）

先**自己新建一个文件夹**当库根 —— 名字随你起，下面这份只是**示意形态**，不是规定：

```
my-assets/                 ← 你自己建的库根（名字随你）
├── index.html             ← 收齐脚本生成的索引页（产物）
├── _manifest.json         ← 产物清单：每条片段的源路径、媒体信息、体积
├── segments/              ← 收进来的片段副本（HTML 原文 + 素材）
└── archive.py             ← 你的收齐脚本（★ 要你自己写）
```

如果三个板块都做，可以长这样：

```
my-assets/
├── <自有板块>     ← 板块① 你自己项目产出的片段集合
├── <上游板块>     ← 板块② clone 来的第三方库（★ 只读）
└── <总览板块>     ← 板块③ 把上面两个合在一页看
```

> **目录名、层数、板块数量都由你定。** 本文只描述这三类板块**各自的性质**，不规定路径 ——
> 你把它塞进已有的目录结构里也行，只要别把「只读的上游」和「可写的自有」混在同一个目录里。

## 二、★★ 核心：归档路上有 6 型「静默假成功」

**这一节是本文的主体。** 每一型的共同特征：**脚本不报错、判据全绿、而产物是坏的**。

### ① 「素材 link 0」≠「没素材」，可能是「没抓到」

静态扫描只认 `src=` / `href=` / `url()`。**JS 里拼的路径一条都抓不到**：

```js
var ASSET = 'assets/';
img.src = ASSET + name;        // ← 这种写法，静态规则全部抓不到
```

**实测代价**：两页 **37 / 24 张图全 404**，而脚本一路打印成功。

**修法**：补「相对目录字面量（`'assets/'`）+ 常见素材目录名（`assets/ imgs/ images/ img/ fonts/ media/ svg/`）」兜底；
且兜底**只收素材扩展名、跳过 `_` 前缀** —— 否则会把 `_gallery.html`、`*.cjs` 也当成素材收进来。

> ★★ 这条还有一个更进一步的形态，见 **§七**：连兜底都抓不到的拼法。

### ② 「暂无成片」≠「本来就没成片」，可能是「源文件丢了」

探测函数（如 `probe_mp4`）对**不存在的文件**静默返回 `None` ⇒ 卡片渲染成「暂无成片」，
看起来像**设计如此**。

**修法**：源不存在时**必须显式告警**，并单独计数（`stats.mp4_missing`）。
★ 关键口径：**`None` 是合法设计，缺失是债 —— 两者必须分开统计**，否则债会被"合法"淹掉。

### ③ 「脚本打印成功」≠「产物能用」

脚本的 `exit 0` 只说明它自己没崩。
**判据必须落在产物上**（真机加载、DOM 断言、肉眼），不能落在脚本的日志上。

### ④ 判据只取「第一个」元素 ⇒ 假 FAIL

**实测**：「计数徽标跟随筛选」这条判据只取了 `vis[0]` 的徽标。
搜 `seg3` 时，**第一个可见段是别的项目** ⇒ 拿到「1 / 3」就判「未跟随」，
而目标段其实是对的。**判据报了红，但红的是判据自己。**

**修法**：**判据必须把它检查过的清单打印出来**，逐项核。只取首元素的判据 = 没验。

### ⑤ ★★★ 「页面自洽」≠「产物 vs 磁盘」—— 源改了但产物没重建

当判据全部在比**页面内部数字互相一致**（DOM 卡数 == 内联卡数 == 卡名集合）时，
**「源新增了内容而产物没重建」这一整类问题完全不进覆盖域**。

**实测**：页面建于 `22:33:51`，27 张新卡落在 `22:39~22:40`
⇒ 页面**静默少 27 张卡**，而 `verify` **23 / 23 全绿**。

更隐蔽的是：那套交叉口径指向的是**上游目录**，而新增内容在**本库补录目录**
⇒ 连「卡名集合」这一项都对得上。

**修法**：**必须补一条独立口径** —— **产物里数出来的集合 vs 磁盘目录扫描出来的集合**。

> ⇒ 收尾自查问法：**「我这条判据，测的是『内容自洽』还是『产物 vs 磁盘』？」**

### ⑥ ★★★★ 「判据能报红」还不够 —— 要问「它**无错**时会不会 PASS」

反例（真实踩到）：一个 `--check` 判据是**直接比字符串**，而产物里写了 `"generatedAt": <构建时刻>`
⇒ **同源、同代码两次构建，字节必然不同** ⇒ 判据**恒报"产物过期"**。

它本来**是唯一能抓 ⑤ 的判据**，却因为**天天喊假警报**而让人学会忽略它
⇒ **真过期那天，警报和噪音一起被忽略。**

**修法**：比对前**归一化掉必然变化的字段**（时间戳 / 路径 / 随机序），
并把「新鲜度」**显式打印**出来：`产物记录的构建时刻 ｜ 产物 mtime ｜ 源最近改动`。

> ★★ **元问法（建议写在每一条判据旁边）**：
> **「这条判据在『没有 bug』的时候会 PASS 吗？」**
>
> —— **「注入故障」只证明了它能报红，没证明它能报绿；而恒 FAIL 的判据照样能通过注入验证。**
> 这是本文最贵的一条。

## 三、流程（五步，第 ③ 步最容易被省）

### ① 摸清库的口径（别急着拷）

- 读库的 README：分类口径 / 设计口径 / 验收记录 / **已知债**
- 读收齐脚本顶部：那份清单通常是**手工策展**的（不是扫出来的）—— 加片段 = 改这个表
- 记住三条固有口径：**按项目分组** · **HTML 原文拷贝不改一个字** · **成片只做相对链接不拷贝**

### ② 改清单，加一条线

```python
{
    "id": "<短 id>", "name": "<显示名>",
    "note": "一句话说明（★ 纯文本，不许有 Markdown 记号）",
    "segs": [
        {"html": "<相对库根的路径>", "mp4": "<成片路径，无则 None>",
         "group": "主线", "variant": "可选，标注变体"},
    ],
},
```

- `html` / `mp4` 都是**相对库根**的路径
- **跨目录也行**（收齐是**读**，不写源项目）

### ③ ★ 重跑前先验源路径（**这一步不能省**）

收齐脚本通常会 `rmtree(seg/)` 再重建 ⇒ **源缺失的片段会被静默跳过 / 静默降级**。

所以重跑前先独立量一遍：

```python
# 把清单里的每条 src 拿去 os.path.isfile 验一遍，打印「片段数 / 源缺失数」
```

**缺失 ≠ 立刻修**。要先判断是「本来就无成片（合法）」还是「曾经有、现在丢了（债）」——
**依据是库的上一版 `_manifest.json`**（它记着当时的 `media` 字段）。
这个区别就是 §二 ② 说的：**`None` 和「缺失」必须分开。**

### ④ 重跑 + 验收

验收分四级，**逐级加强，不能跳**：

| 级 | 抓什么 | 备注 |
|---|---|---|
| ① 静态 | 断链 | ⚠️ **只当初筛** —— 抓不到 JS 拼接路径（§二 ①） |
| ② 真机加载 | 404 / JS 错误 / 空图 / 容器 `kids=0` | ★ **金标准** |
| ③ DOM + 交互 | 分组数 / 卡片数 / chips / 统计卡；筛选 / 搜索 / 预览层 / 窄屏 | |
| ④ 肉眼审判 | 截图 **≥8 张**逐张看 | 数值全绿也要走这一步 |

**库级必须加的 DOM 断言**：

- `section.project` 数 == 项目数；`.card` 数 == 片段数
- **计数徽标跟随筛选** —— ★ 必须筛**子集**（筛全集看不出差别），且**逐段核**（§二 ④）
- 预览层 `<video>`：`readyState` + **盒比 vs 源比**（判有没有变形）
- 全文扫 `**` / 反引号残留（Markdown 记号漏进纯文本）
- 统计卡数字与 `_manifest.json` 对得上

### ⑤ 更新 README + 登记债

- **快照行**：项目 / 片段 / 带成片 / 总时长 / 素材 / 体积
- **验收记录**：新增一段（日期 + 动作 + 结果表 + **肉眼揪出的缺陷**）
- **归档债**：源侧丢了的成片 / 素材，逐条列表 + **现成副本位置** + 修复方案

> ⚠️ **不许悄悄降级**。债就是债 —— 如实登记，让决策者选
> 「恢复源侧 / 库内回退 / 接受现状」。

## 四、★ 重跑纪律（血的五条）

1. **重跑前先留底产物** —— `cp index.html _tmp/index.stale-<时间>.html`。
   ★ 留底那份是**最好的负控**：判据修完后拿它一比，**必须仍报"不一致"**；
   报"一致"就说明**你把判据弄瞎了**。
2. **重跑后必须验「重建是否零损失」** —— 归一化掉构建时刻字段后**逐字符**比新旧产物。
   **实测**：某页归一化 `builtAt` 后新旧**完全相同（579,159 字符）** ⇒ 才敢说"没覆盖任何手改"。
3. **别拿 md5 判「重建有没有改动」** —— 产物里带构建时刻时，**md5 不是内容指纹**。
   先查：产物里有没有 `generatedAt` / `builtAt` 这类字段？
4. **确定性要实测**：连跑两次比 md5。相同 ⇒ 幂等，可放心重跑；不同 ⇒ 先找那处非确定性，再谈验收。
5. **清单类数字（项目数 / 片段数 / 总时长 / 条数）必须「跑一遍脚本」得出，不能手抄。**
   **实测**：某 README 记「9 项目 / 34 片段」，实跑是 **11 / 41**
   （清单早加了两个项目，文档没跟上）。
   ⇒ 与「规模类判据要来自真加载器，禁 `grep` / `wc`」同族。

## 五、清单本身怎么改（四个坑，全是「改了却像成功」）

| 坑 | 症状 | 正解 |
|---|---|---|
| **插入锚点不含 `]`** | 锚点写成 `    },\n]\n` 再「在其后插入」⇒ 新块落在**列表外面** ⇒ 报 `unexpected indent` | 锚点**必须含 `]` 本身**；且先 `count == 1` 预检 |
| **只改不验语法** | 写完才发现库跑不起来 | 改完立刻 `ast.parse(new)` **再** `py_compile(..., doraise=True)` 实跑；不过就**一个字都别落盘** |
| **用 `ast` 取 dict 的**值 | 用 `d.keys[0].value` 取 id ⇒ 打出一串 `id, id, id, …`（那是**键名**字面量） | 值在 **`d.values[0].value`**；用它自证「老条目一个不少 + 末位是新条目」 |
| **断言字段名凭印象** | 按 `html` / `mp4` 写回读断言 ⇒ **三条假红** | **先 `json.load` 打一眼真实键名再写判据**（实测真身字段是 `src_html` / `src_mp4` / `media` / `assets` / …） |

## 六、页面上容易翻车的字符

| 坑 | 症状 | 修法 |
|---|---|---|
| Markdown 记号漏进纯文本 | 页面上真出现反引号或 `**` | 去记号 ＋ **加断言**（字段不许含记号） |
| 生僻 Unicode 图标 | `&#8851;`（⊓）渲染成 `n` | 换 emoji（`&#128203;` 📋）或纯文本 |
| 占位符与属性名同名 | `window.{...} = {...}` 语法错误 ⇒ **整页空白** | 用 `/*__DATA__*/null` 这类不可能碰撞的形态 |
| Python 串里的 `\u` | `SyntaxError: truncated \uXXXX escape` | 模板里写 `\\uD83D\\uDCCB`（转义反斜杠） |
| `console.log` 宽度修饰 | `%-16s` 不被 Node 支持 ⇒ 参数错位、输出 `NaN` | 用 `String.padEnd()`，别用 printf 语法 |

## 七、★★ 兜底也抓不到的拼法：路径跨了目录段

```js
const srcT = 'renders/tex/f' + f4 + '.png';   // ← 连兜底规则都抓不到
```

**为什么连兜底都抓不到**：

- 不是成对的 `src="…"` ⇒ 不匹配引用规则
- 也不是「引号里的**单段**目录字面量」⇒ 那条规则要求 `['"][\w-]{2,20}/['"]`，
  而 `renders/tex/` **含斜杠**，不匹配
- `renders/` 又不在常见素材目录白名单里

**⇒ 结果是：脚本不报错**（该段照样打「缺失 0 / 素材 link 5」）
⇒ **又一型静默假成功**：库里的页面"收齐了"，实际画面跑不出来。

**处置三步**：

1. 清单的 `note` / `group` 里**写明缺口**；
2. 总档「遗留」单列 + 给候选修法
   （A 给收齐脚本加 per-seg 的 `extra_dirs`；B 工程内另存一套低分预览帧专供库内播放）；
3. **不许假装能跑**。

> ★★ **证明缺口要两侧都量**：库内该帧**不存在** + 源工程侧**存在**
> （实测某轮：源侧 3.9 MB / 张）⇒ 才能下结论「**是没抓到，不是没有**」。
> **只量一侧 = 猜。**

## 八、归档后收尾核验（fresh 扫盘清单，别盲信 manifest 计数）

1. **跑前快照** 各系列文件数 + 文件总数 → **跑后逐系列对账**（判据：**老系列零漂移**）。
2. **幂等判据**：连跑两次收齐脚本，`_manifest.json` **与** `index.html` 的 md5 必须**逐字节一致**。
3. **入库 HTML 与源码 md5 一致 + mtime 一致**（是实体拷贝，不是链接）。
4. **manifest 里的媒体信息 与 你自己 `ffprobe` 的实测三点全等**（w/h、frames、dur、bytes）
   —— ★ **交叉校验，不互相抄**。
5. **`assets` 里每一条都要在库内真实存在**（防「登记了却没拷」）。
6. **成片链接要按 `mp4_rel_from_index` 解出来扫**（不是照抄字符串判空）。
7. **`!!` 行逐条归因**：跑完扫一遍 `!!` 开头的行，**按系列归类** ——
   「缺失 11 / 断链 3」里，**属于本系列的是几条**才是结论
   （实测某轮：3 条全属别系列 ⇒ **本系列 0 条**）。

## 九、已知边界

- **「自包含」承诺的前提是源素材还在。** 源丢了就是**债**，不是靠脚本能变出来的 ——
  如实登记，让决策者选「恢复源侧 / 库内回退 / 接受现状」，**不要**用魔法回退掩盖。
- **静态扫描抓不到 JS 拼接路径** ⇒ 兜底是必需的，但兜底要**限定扩展名 + 跳 `_` 前缀**。
- **硬链接去重依赖同卷**；跨卷自动退化为复制（行为正确，只是不省空间）。
- 库的 `index.html` 里「成片」链接若指向 `../../<原项目目录>` ⇒
  **移动库目录会让成片链接失效**（源码不受影响）。
- **没有 HTML 交付物的线进不了这类库** —— 模型以 HTML 为入口。
  纯 3D 渲染的片如实说明「无 HTML 交付物 ⇒ 不入册」，
  **别为凑数塞个假入口**。

## 十、一句话

这套东西的价值不在于它能**建**一个库，
而在于它承认 **「判据会骗人」**，并为「库里的页面看起来长好了、其实是空的」这一类问题
留了**六道显式的检查**。

> **判据能报红不算数，能在没 bug 时报绿才算数。**
