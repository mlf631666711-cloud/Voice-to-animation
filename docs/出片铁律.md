# 出片铁律

> 这不是"最佳实践建议"，是**违反就要返工**的红线。
> 每一条都对应一次真实翻车，后面括号里是它的记录编号。

---

## 一、时长与音画

### 1. 片长听配音的，不是听"计划"的

```
成片时长 = 配音时长 + 1.000 秒     实测偏差 |Δ| ≤ 0.02 秒
```

末尾那 1 秒是留给呼吸的。**永远不要用"我打算做 30 秒"去定长** —— 分镜表里的时长必须是
从配音实测（`ffprobe`）推出来的。语速变 5%，整片节奏就全歪。

### 2. ⛔ 合成时禁用 `-shortest`

用 `-shortest` 实测得到 **349 帧**，而正确做法是 **353 帧** —— 少的这 4 帧（约 0.12 秒）表现为
**末尾画面已经静止，人声还在念**。（BUG-2328）

```bash
# ❌ 别这么写
ffmpeg -i frames/%05d.png -i voice.wav -shortest out.mp4

# ✅ 时长显式对齐，让音频自然结束
ffmpeg -framerate 30 -i frames/%05d.png -i voice.wav -c:v libx264 -crf 18 -pix_fmt yuv420p out.mp4
```

### 3. 双版本（有音效 / 无音效）画面只渲一次

```
第一次：渲画面 + 合成 A 版音频        →  成片A.mp4
第二次：ffmpeg -i 成片A.mp4 -i B.wav -map 0:v -c:v copy -map 1:a ...  →  成片B.mp4
```

重渲一遍画面不只是慢一倍 —— **两次渲染的结果可能不完全一致**（浮动、随机、字体加载时序）。
`-c:v copy` 保证两版画面**逐帧 md5 相同**。

### 4. 判据口径 = **真实渲染状态**

量出来的数、判过的绿，必须来自**真正在跑的那个产物**。
"我改了源码" ≠ "产出变了"；"打包成功了" ≠ "双击起来是新版"。
中间产物过期是**静默**的：`returncode == 0` 不是证据，**产物真写出 + 验新鲜度**才是。

## 二、构图与画面

### 5. 字幕净空：安全框内元素底边 ≤ 880（1080p）

字幕条从 `y = 900` 起。任何元素压上去都会糊成一团。
交付前跑 `node kit/boxchk.js`（含坐标系自检，视口错配时它输出 `N/A` 而不是假的 PASS）。

### 6. 调试辅助元素必须有一层**结构性**的兜底关闭

三分线 / 安全框 / 栅格 / 四角括号 —— 这些调景用的辅助线**烧进成片**过（BUG-2694）。
细虚线在缩略图、亮度统计、帧率检查里**全都看不见**，只能把成片抽帧放大才看得到。

正解不是"某个函数里加个 if"，而是**在 CSS 层兜底**：

```css
body.export .guides { display: none !important; }
```

（放 CSS 的原因：导出的固化 HTML 会带上同一条规则；`!important` 能盖过 JS 内联样式。）

### 7. 与画布坐标有关的定位，别写 `left:50%; top:50%` 就完事

一个元素若同时被 `left/top:50%` 和 `transform: translate(x%,y%)` 定位，而 `translate` 里**没有 −50% 补偿**，
它会只露出右下 1/4。（BUG-2693）

更值得记住的是它能藏住的原因：**当时 7 条判据全绿** —— 它们量的是"有没有画面、动没动"，
**没有一条量"画面在框里的什么位置"**。

> **几何类缺陷（偏移 / 缩放 / 裁切）只能靠几何判据抓。像素差和"有没有内容"永远抓不到它。**

## 三、动效与渲染

### 8. 缓动：入场 `easeOutBack`，位移延展只用 `linear`，**其余禁 linear**

`linear` 入场看起来像卡顿。但**末段延展**例外 —— 那一段要的就是匀速，用缓动反而会在结尾"顿一下"。

### 9. 末段零定版

**不做末尾冻结**。末镜的动作演到片尾自然结束。
冻结会让尾段塌成静帧，观众感知为"卡住了"。

### 10. 渲染/截图前必须隐藏起播遮罩

这是**最高频的一击**：遮罩没隐藏 ⇒ 成片**一片白**，而且**零报错、判据全绿**。（BUG-2358 / 2365）

> 交付前一定抽一帧出来看。别信"渲染成功"。

### 11. 同一工程、同一时刻只跑一个渲染

两个渲染进程抢同一份 `frames/`，会互相覆盖中间帧 —— 而**最终产物看起来"基本正常"**，
只有几帧是错的。（BUG-2359）

### 12. 4K ≠ 把尺寸调大

给按 1080p 设计的 DOM 页面直接传 `--w 3840`，得到的是「**4K 外壳 + 左上角嵌一张 1080p**」，
而**文件尺寸判据照样 PASS**。（BUG-2395）

正解 = **视口保持设计尺寸 + 超采样（`deviceScaleFactor=2`）**。

### 13. `Promise.race` 不是 canceller

`Promise.race([任务, 超时])` 只是"不再等它"，**任务本身还在跑**。
4K 场景下表现为每片白等 299 秒。（BUG-2413）

真要取消，得取消底层句柄（`AbortController` / `kill` 子进程）。

### 14. 改完带动画的对象，必须回读断言

给一个**会被帧求值覆盖**的字段赋值，改了等于没改 —— 下一帧求值时它又被算回去了。
表现为"我明明改了，画面没变"。

## 四、验收（最容易自欺的一节）

### 15. 判据必须**有牙**：故意做错一次，看它会不会红

一条判据如果**不可能失败**，它给的绿就没有意义。

> 实例：某判据是**恒 FAIL** 的，而它照样通过了"注入故障验证" ——
> 因为注入只证明了**它能报红**，没证明**它能报绿**。两件事都要验。

### 16. 阈值必须**实测**得出，禁手填

- 教训 A：自己设了个 `8070` 当上限 ⇒ **假 PASS**。上限得从真实分布量出来。
- 教训 B：基准值手填 `p95 = 215`，实际是 `80 / 169` ⇒ **整轮结论方向反了**。

基准值必须**能从产物复现**；写进文档的每个数，都要能说出它是怎么算出来的。

### 17. ⭐ 指标对上 ≠ 看起来像

自动判据只能判**假绿**，不能判**真假**。

收工前必须做一次**同尺度 A/B**：把成片抽帧和页面同帧截图，**两边各自对齐到同一尺寸**，
再逐像素比、并排贴一起用眼睛过一遍。

> 本项目实测统计：**9 个典型缺陷里 8 个不会报错**。
> 能不能发现问题，取决于你有没有把成片抽帧摊开看。

### 18. 度量本身也可能坏

用 ffmpeg `blend=difference,scale=1:1` 对**肉眼差异巨大**的两张图，只读出 `0` 和 `2`。
最严重的后果不是"判据松"，而是它把真实缺陷（**两边走了同一条错路**）显示成了 **Δ=0 的满分绿灯**。（BUG-2695）

> **「Δ ≈ 0 太漂亮」本身就是一个必须追查的信号**：先问"这两个东西是不是根本没被区分开"。

改用 Python 逐像素（PIL + numpy，缩到 480×270 取平均绝对差）后，实测基线：
正常 `0.75` / 负控 `34.56` / `37.04`。

### 19. 一条 A/B 判据必须带**单变量负控**

只差一个变量，才能分清是谁的锅。没负控的 A/B 只能证明"两边长得像"，
不能证明"我的改动真的生效了"。

### 20. 交付级作品必须换人二审

自己做的东西，自己看不出来。找一个**没参与制作**的人，8 个维度各打分，**目标 ≥90**。

## 五、工程纪律

### 21. 含反引号 / 复杂转义的内容一律写脚本文件

内联进 shell 会被吃掉 —— 后果是**标识符变成空串，而退出码仍然是 0**。

### 22. 删文件前先 grep 引用闭包

删掉的可能是别人（或三个月后的你）正在依赖的东西。

### 23. 重跑只要 2 分钟的产物，不存盘

存的是「**怎么重跑**」，不是产物本身。结论进文档，抽帧图删掉。

### 24. 改真源，不改产物

跨写者纪律：**改前留底 / 改后回读**；同一个文件**禁止并发写**。
