# 美学与排版准则

> **这份不是审美意见，是把本项目「已经在用的」阈值、取向与禁令反向抽出来的宪法。**
> 每一条后面都标了**出处**——数字不是编的，是可以回查的：工具改了，这里必须跟着改，否则它立刻从"宪法"退化成"传说"。
>
> **和《出片铁律》的分工**：
> 《出片铁律》写「**违反就返工**」的硬线（会报错、会被判据拦下的那些）；
> 这份写「**看起来高级还是廉价**」的取向，以及**把取向落成数字**的那一层。
> 两份都要过，但过的方式不同：铁律靠判据拦，这份靠**开工前读一遍 + 交付前肉眼过一遍**。

---

## 〇、为什么"美学"也需要硬数字

因为这套管线里，**观感问题几乎都不会报错**。

本项目的实测统计：**9 个典型缺陷里 8 个不报错、判据全绿、画面是错的**。
「颜色不够高级」「留白太挤」「字号没有层次」全在这个区间里——它们既不越界、也不违规、
`trial.js` 的八条红线一条都不会红。

所以这份文档的写法是：**凡能变成数字的，一律变成数字**；
**变不成数字的（"高级感"），说清它由哪几个可量的东西合成**。

## 一、画布与三层安全区

设计坐标固定 **1920×1080**（所有几何判据都按这个坐标系写死，改画布等于全部判据失效）。

| 层 | 范围（设计坐标） | 含义 | 谁在量 |
|---|---|---|---|
| **安全框**（最外） | x[52, 1872]　y[70, 1008] | 元素的**硬边界**，出了就裁切 | `kit/boxchk.js` |
| **主元素区**（内） | x[80, 1840]　y[80, 880] | 主体内容的**建议区**，比安全框更保守 | `kit/layout_check.js` |
| **字幕净空带** | y[900, 1080] 全宽 | 留给字幕条，**不放任何元素** | `kit/layout_check.js` |

三者的关系是**嵌套**：主元素区 ⊂ 安全框，净空带在外侧下方。

> ⚠️ **两个最容易错的点**
> 1. **880 与 900 是两条不同的线**，中间 880~900 是缓冲带。把 880 当"净空线"是常见的错——
>    它其实是**主元素区的下界**。
> 2. **HUD 类元素（角标 / 单位 / 时间码）要显式声明**（`data-hud="1"`）才能走另一套更宽的边界；
>    **不许做"看着像 HUD 就算 HUD"的推断**。判据不给模糊地带留后门，是故意的。

**留白**：主元素区 1840×880 里，主体内容的实际占位建议 **≤ 70% 面积**；
四周留白少于 80px 就会显得"顶格"，而顶格是廉价感最直接的来源之一。

## 二、字号阶梯

### 先记一条会改变判据口径的硬线

```
字号 ≥ 24px            → 算「大字」，对比度门限 4.5 → 3.0
字号 ≥ 18.66px 且加粗  → 同样算「大字」
否则                   → 正文口径，门限 4.5
```

（出处：WCAG 2.1；`kit/contrast_check.js`）

⇒ **字号决策不只是审美，它会直接换掉判据的尺子。** 同样的颜色，21px 要过 4.5，24px 只要过 3.0。
所以「顺手把标题从 22 调到 24」这种改动，必须重跑对比度。

### 实测：本库在用的字号

全库（`kit/` + `kit/templates/`）实测分布：从 **11px 到 96px**，另有 216px 的特例；
出现最密的档位是 **12 / 14 / 17 / 22 / 24 / 26**。

基于实测收敛成 **6 档**（新工程照这个走，别自由发挥）：

| 档 | 字号 | 行高 | 用在哪 | 字距 |
|---|---|---|---|---|
| **H1 主标题** | 96~120px | 1.1 | 片头 / 章节题头，**一屏只放一个** | 0~0.02em |
| **H2 次标题** | 64~80px | 1.15 | 章节内主句 | 0~0.02em |
| **L 大字** | 40~44px | 1.2 | 关键句、被强调的数字 | 0 |
| **正文** | 26~34px | 1.3 | 主要阅读量 | 0~0.02em |
| **说明** | 19~22px | 1.35 | 卡片正文、注释 | 0.02~0.04em |
| **标签** | 14~17px | 1.2 | 角标、单位、HUD | 0.04~0.12em |

**层级差**：相邻两档至少差 **1.3 倍**。差得太近（例如 26 与 30 并存）观众读不出层级，
画面会"糊成一团"——那是比"丑"更糟的观感问题：观众知道有问题，但说不出哪里。

**正文下限**：正文类不要低于 **19px**。低于这个数在缩略图里"看着像噪点"，
而且它会掉进 4.5 的对比度口径——**同一套配色，正文忽然不达标**。

**标签要放开字距**：小字号必须加大字距（0.04em 起），否则密集笔画会粘死。

## 三、对比度

| 项 | 门限 | 出处 |
|---|---|---|
| 正文（< 24px，或 < 18.66px 的粗体） | **≥ 4.5 : 1** | WCAG 2.1 · `kit/contrast_check.js` |
| 大字（≥ 24px，或 ≥ 18.66px 且粗体） | **≥ 3.0 : 1** | 同上 |
| 贴地板线的余量 | **≥ 10%** | 同上（`floor` 系数 1.10） |

> ⚠️ **别把余量系数放大**。系数调到 1.25 之后，一处本来余量 21% 的地方会被报成"贴地板线"，
> 于是**真问题淹没在假警报里**。1.10 这个数是从「只余 0.7%」的那个真实案例标定出来的。
> 判据的松紧是用**实测案例**定的，不是拍脑袋定的。

### 主题自检（`kit/themes.js` 的 `audit()`，5 条）

| # | 查什么 | 门限 |
|---|---|---|
| S1 | 10 个语义色角色全部有合法色值 | 10 / 10 |
| S2 | **墨 vs 纸**对比度 | ≥ 4.5 |
| S3 | **强调色 vs 纸**对比度 | ≥ 2.0 |
| S4 | 墨 / 纸 **亮度差** | ≥ 0.20 |
| S5 | ★ **纸 vs 背景**对比度（承托块不能隐形） | ≥ **1.15** |

> **S5 是后补的**，而且是**肉眼审判补出来的**——原判据只验「墨 vs 纸」，
> 漏了「纸 vs 背景」，而正是这一条决定承托块看不看得见。
> 教训：**一对一的对比度检查会漏掉"层与层之间"的关系。**
> 新加一层背景 / 一个承托块，就补一条它和邻居的对比度。

## 四、配色与主题

5 支主题（`kit/themes.js`），按片子类型选，**不按个人喜好选**：

| id | 取向 | 底 | 标题字重 | 字距 | 颗粒 |
|---|---|---|---|---|---|
| `dark-tech` | 深底科技 | 暗 | 600 | 0.02em | 0.045 |
| `light-product` | 白底产品页 | 亮 | 700 | 0.01em | 0.012 |
| `ink-paper` | 浅底纸感（低饱和） | 亮 | 600 | 0.03em | 0.055 |
| `warm-media` | 暖底高对比（口播 / 种草） | 暗 | 700 | 0.01em | 0.05 |
| `c5-tiny` | 近纯黑 + 金属金（发布会向） | 暗 | 900 | 0.01em | 0 |

三条取向（比色值重要）：

1. **一个画面只有一个强调色在发光。** 强调色超过一处同时高亮 = 观众不知道看哪儿。
2. **颗粒（noise）是"高级感"的主要来源之一，但必须极轻**——0.012~0.055 是实测区间，
   超过 0.06 就从"质感"变成"脏"。
3. **亮底主题的标题字重要提到 700**（白底上细字会糊），暗底可以回到 600。

## 五、动效节奏 —— 时间的"排版"

出处：`kit/motion-tokens.js`。**节奏是排版的一部分**：字号管空间层级，时长管时间层级。

### 元素级（秒）

| 档 | 时长 | 用途 |
|---|---|---|
| `micro` | 0.10 | 图标点一下、数值跳动（再短就看不见） |
| `fast` | 0.15 | **高频元素**（≥3 次出现的）专属档 |
| `base` | **0.22** | ★ 默认。绝大多数元素 |
| `slow` | 0.30 | 大元素、需要被读清的卡 |
| `hero` | 0.50 | 主视觉入场、整组错峰上限 |
| `maxMove` | 0.60 | **大位移硬上限**，超过就是拖沓 |

### 摄影机级（秒）—— 另一套刻度，禁止与元素共用

| 档 | 时长 |
|---|---|
| `snap` | 0.55 |
| `quick` | 0.90 |
| `push` | **1.60**（标准推镜） |
| `slow` | 3.00（长距离飞行） |

> 元素用 0.22、摄影机用 1.60——**同一支片子里两套刻度并存是正常的**，
> 它们管的是两种尺度：元素在"到达"，摄影机在"移动"。

### 四条硬规矩

| 规矩 | 值 | 为什么 |
|---|---|---|
| 退场 = 入场 × **0.60** | — | 进入要减速到位（它在抵达），离开要加速走人（它在让位）。同一条曲线进+出 ⇒ 退场"恋恋不舍" |
| 错峰间隔 | **30~80ms**，整组 **≤ 500ms** | 错峰是"依次"的观感；超过 500ms 观众会读成"卡住了" |
| 大小元素时长比 | **≥ 1.5 : 1** | 差得不够，层次会糊 |
| 元素**禁** `linear`、**禁** `ease-in` | — | linear 入场像卡顿；ease-in 入场会被读成"迟疑"。**例外：末段匀速延展**要的正是 linear |

### 三条强曲线（原值，不是近似）

```
入场主力    cubic-bezier(0.22, 1, 0.36, 1)    强减速
重量感入场  cubic-bezier(0.16, 1, 0.30, 1)    暴冲后极缓收尾
位移 / 运镜 cubic-bezier(0.65, 0, 0.35, 1)    对称 in-out
```

### 一票否决（`MOTION.audit()` 会直接判 FAIL）

- 元素动效用 `lin`
- 元素入场用 `ease-in`（`ei` / `qi` / `xi` 一类）
- 元素时长 > **0.60s**
- 元素时长 < **0.08s**（30fps 下不足 3 帧，会看成瞬移）→ WARN

## 六、构图与层次

| 手法 | 实测参数 | 作用 |
|---|---|---|
| **三层视差** | `bg / mg / fg` 分别按 **0.3 / 0.6 / 1.0** 速率位移 | 防"PPT 感"的关键；平铺不动 = 一眼廉价 |
| **暗角** | `radial-gradient(120% 92% at 50% 48%, 透明 38% → rgba(0,0,0,.58) 100%)` | 把注意力收向中心 |
| **网格底纹** | **80px** 方格，不透明度 0.8，随呼吸 0.92~1.00 微动 | 提供"活在动"的底噪，避免死帧段 |
| **安全框自检** | 见 §一 | 几何缺陷**只能靠几何判据抓** |

**两条比参数更重要的**

1. **元素跨镜要接得住。** 上一镜的东西凭空消失、下一镜的东西凭空出现，观众会读成"剪辑事故"。
   （`kit/carry_check.js` 就是量这件事的）
2. **末段不做冻结定版。** 末镜的动作演到片尾自然结束；冻住会让尾段塌成静帧，
   观众感知为"卡住了"。**"留白"和"停住"是两件事。**

## 七、一票否决清单（开工前过一遍）

- [ ] 起播遮罩在渲染前被显式隐藏（**命中率最高的一条**：不隐藏 ⇒ 成片一片白、零报错）
- [ ] 调试辅助线（三分线 / 安全框 / 栅格）有一层 **CSS 兜底**关闭，不靠某个函数里的 `if`
- [ ] 合成命令里**没有** `-shortest`
- [ ] 元素 `left/top:50%` + `transform:translate(x%,y%)` 的地方，**有 −50% 补偿**
- [ ] 4K 是"视口保持设计尺寸 + 超采样"，**不是**把 `--w` 调大
- [ ] 同一工程同一时刻只跑一个渲染
- [ ] 每个镜头的时长都来自**配音实测**，不是"我打算做 N 秒"
- [ ] 字号跨档时重跑了对比度（因为 24px 会换尺子）

## 八、怎么验（每条准则都配一个能跑的判据）

```bash
node kit/check_spec_lock.js --dir <工程目录>   # 参数有没有漂（锁 vs spec.json）
node kit/trial.js <工程.html>                  # 总审判器：8 条 P0 红线
node kit/layout_check.js --file <工程.html>    # 四边 / 字幕净空 / 重叠 / 元素数
node kit/boxchk.js --file <工程.html>          # 安全框（含坐标系自检）
node kit/contrast_check.js --file <工程.html>  # 对比度（Otsu + WCAG）
node kit/carry_check.js                        # 元素跨镜连续性
```

**但这些只覆盖"能变成数字的那一半"。** 另一半——"高级还是廉价"——**只有眼睛能判**：
交付前把成片抽帧，和页面同帧截图**各自对齐到 1920×1080**，并排贴一起过一遍。

> 这两关缺一不可。
> **只有机器**，你会交出一堆"判据全绿但画面是错的"；
> **只有眼睛**，你会在 300 帧里漏掉第 217 帧。
