## 这一层解决什么

写 `spec.json` 时，`enter: fadeUp` / `cam: punchIn` 这类字段**是个裸枚举** ——
没人知道当初为什么选它、参数该给多少、有什么坑。而镜头卡库里有：

| 卡片带的东西 | 我们原来有没有 |
|---|---|
| **参数表 + 调节手感**（"3–4f 是甜点；<2f 整行齐入没有 stagger；>8f 观众开始数词"） | ❌ 没有 |
| **已知坑**（含中文适配：`split(' ')` 在中文上得到一整块） | ❌ 没有 |
| **可播样片**（214 个）+ 悬停即播预览页 | ❌ 没有 |
| **判例式审美准则**（27 条 R/Q/S/C/P） | 有零散的，不系统 |
| **能量/时长/适用**结构化字段 | ❌ 没有 |

**但两个库的设计前提不同，不能直接套**（见下节两把尺子）。

## 在管线里的位置

```
wav ──faster-whisper──► 逐词时间轴 ──► 分镜表(spec.json)
                                          ▲
                          ┌───────────────┘
                          │  ★ 新增：分镜选型层
                          │
              ① 逐镜写「动效意图」  ← 人/AI 的语义判断（工具不猜）
                          │
              ② pick.mjs --intent "<动效语汇>" --dur <实测秒>
                 ⇒ 候选卡 + 时长对账 + 参数手感 + 已知坑
                          │
              ③ 定案：写进 spec 的 card{shot,cam,variants,why}
                          │
              ④ pick.mjs --from-spec  ← 审计：卡名真实性/时长/同质化(P4)
                          │
              ⑤ verify.mjs <spec>      ← 结构自洽 + 审美准则核对表
                          ▼
                    手写 HTML 动效 ──► 截帧审判 ──► 渲染 ──► 成片
```

**一句话**：选型层只加在**分镜阶段**，不动渲染链。卡片是"词汇表 + 参数源"，
**不替代 `kit/` 的纯函数驱动层**（上游是 Remotion/TSX 栈，我们是 HTML+JS 纯函数栈）。

## ★★★ 三把尺子（实测出来的三个结构性差异，必须先知道）

### ① 旁白 ≠ 动效意图 —— **别拿旁白直接去搜卡**

实测（本库工具，2026-09-22）：

| 查询 | top1 | 相关度 |
|---|---|---|
| 「视频链路还涉及 PSRAM,」（**旁白原句**） | `cube-navigation` | **0.05** ← 噪声级 |
| 「数字滚动 指标增长 内存占用不断上升」（**写成动效语汇**） | `odometer-digit-roll` ✓ | **2.35** |

**差 46 倍**。根因：**旁白说的是"内容"，卡片写的是"运动语法"** —— 两个语义域。

> ⚠️ 最危险的地方不是检索不准，而是它**照常输出一份漂亮排名** ——
> 看着在工作，实际在算命。

**⇒ 纪律**：`旁白 → 动效意图` = **语义判断，由人/AI 做**；
`动效意图 → 候选卡` = **检索，由工具做**。工具不许假装能做前者。
（`pick.mjs --from-spec` 因此**故意不自动出候选**，只做确定性审计。）

### ② 我们的镜比卡片短得多 —— **卡片只能拆段取用**

实测本线 5 个工程的 30 个真实镜 vs 150 张镜头卡：

| | 中位 | p75 | 最大 |
|---|---|---|---|
| 我们的镜长（`t1−t0`） | **2.10s** | 2.51s | 4.24s |
| 卡片典型时长（下界） | **4.00s** | — | — |

**97%（29/30）的镜短于卡片下界中位数**，典型差 **1.90s ≈ 57 帧**。

原因：卡片库是为「一镜 4–5s、按能量弧线分段」的宣传片设计的；
我们这条线是**语音轴驱动** —— 镜长由"说这句话要多久"决定，天然密。

**⇒ 四条压缩策略**（`pick.mjs` 会按镜长自动给到对应那条）：

1. **只取卡片的一个阶段**（入场段 / 落定段），把后续 hold 砍掉 —— 最常用；
2. 按卡片**「参数手感」列**往下压 —— 但每个参数手感列里都写了下限（`<2f 没有 stagger`）；
3. **减词**比压参数安全（stagger 总长 = `gap × 词数`）；
4. 实在压不下 ⇒ 让动效**跨两镜完成**（前一镜起手、后一镜落定）—— 语音轴天然适合。

省力入口：卡片库里有 **42 张「短镜友好」卡**（存在 ≤3s 的用法），优先从这里挑。

> ⚠️ **禁**拉伸曲线来"用满"镜长（上游 R3：放慢可以，拖长会散）。

### ③ 用**卡片自己的说法**去搜卡片 —— **要两轮检索**（2026-09-22 真实工程实测加入）

拿**真实工程** `projects/rv1106-seg5`（7 镜）跑了一遍，**同一镜、同一语义、只用词不同**：

| 意图写法 | rel | top1 |
|---|---|---|
| 我们的说法：「卡片**堆叠成摞** 扇形散开 延迟错落」 | **0.67** | `magician-card-flourish` ❌ 不对口 |
| 卡片自己的说法：「卡片 **spring 弹入叠成一摞 展成扇面 3D**」 | **6.03** | **`card-stack`** ✅ 完全对口 |

**差 9 倍。** ⇒ **卡片库是自洽的一套语汇；近义改写不算数，要往卡片的话术靠。**

**⇒ 两轮检索**：
1. 第一轮：写自己的动效意图去搜；
2. 看 top1 的**「一句话」**，把里面的动效词**抄进**意图，**再搜一次**。

> 实测收益：该工程 7 镜一轮命中 **1/7（14%）** ⇒ 两轮后 **5/7 对口 + 1 半对口（71%）**。
> 两轮后仍 `< 1.2` ⇒ 多半是**卡片库真没有这个动效**（该工程镜 4 两轮都是 0.52）
> —— 这是**库存缺口**，别再换词硬凑，直接自己写（或拿技法卡组合）。

### ③的配套纪律：对象词决定对错，运动词决定排序

`type-*` 系列是**吸铁石卡** —— 正文塞满「入场 / reveal / stagger / 合拢 / 逐字」这类**通用运动词**。

实测：镜2「**双卡**并排入场」、镜5「**三卡**并列 横排 stagger 入场」的 top1 **都曾是**
`type-assembly-moves`（**文字系卡**，四式全是字符级动画）—— **7 镜里 2 镜中招（≈29%）**。
换成英文近义词 `three cards side by side entrance` **照样中招**
⇒ **不是中文分词问题，是检索里缺「对象类型」这一维**。

**⇒ 意图语汇必须写「对象词 + 运动词」两段**：

```
❌ 三卡并列 横排 stagger 入场              → 被 type-assembly-moves 吸走
✅ 三卡并列 横排 stagger 入场   ← 有"卡"（对象词）就够，工具自动降权错配候选 −1.50
```

`pick.mjs` 已落地：命中对象词而候选是文字系卡 ⇒ **降权 −1.50（不剔除）+ 打印警告**。

> ★ 词表维护：对象词表含裸「卡」但**排除「卡点」**（节奏术语，不是对象）。
> 第一版只写了「卡片」⇒ 「**三卡**并列」漏判过一轮 —— 加词表时记得**负控**
> （「卡点 逐字 入场」不该降权、「文字逐字入场」不该降权）。

$NODE kit/shotcraft/pick.mjs --intent "并列参数 文字reveal 专业不抢戏" --dur 2.9
$NODE kit/shotcraft/pick.mjs --intent "数字滚动 指标增长" --dur 2.1 --cat data

$NODE kit/shotcraft/pick.mjs --from-spec projects/xxx/spec.json

## ★★ 文案 → 动效设计方案（2026-09-22 接入**第二个**知识库）

老板原话：「针对我给你的文案，你去自动加工设计一下这个动效**怎么写、怎么说**」。

原有一条线只接了**一个**库，不够用 —— 因为写分镜表要同时回答两个问题：

| 库 | 粒度 | 规模 | 字段 | 回答什么 |
|---|---|---|---|---|
| `video-shotcraft`（本资产库） | **镜头级** | 157 张 | 一句话 / 时长 / 能量 / 参数手感 / 已知坑 | 这一镜**整体是什么结构**（含时长对账） |
| **`动效设计师`**（`<你的术语库>` · 每日自动扩库） | **术语级** | **558 条 / 36 类** | cn / en / desc / **params** / use / **how** / demo / tags | 具体**怎么写**（参数 + PR/AE/剪映/CSS 实现）+ **怎么说**（术语名） |

> ⚠️ 术语库是**别人家的活库**（每天自动 +20 条，带幂等锁）：`term.mjs` **直接读它的源分片，不复制数据**，
> 用 mtime+size 指纹判新鲜度（`revision` 变了就是源库更新了）。

### 三步分工（**不许合并** · 铁律 181）

```
① 读文案 → 切镜 → 给每镜写「动效意图」   ← 人 / AI 做（语义判断）
② 意图 → 术语库 + 镜头卡库检索、时长对账、重复检查、幻觉 id 校验 ← plan.mjs 做（确定性）
③ 「这镜到底怎么落地」的取舍             ← 人 / AI 做（写进 note）
```

### 四条命令

```bash
NODE="node"

# ⓔ 术语库（558 条）——"怎么写 + 怎么说"
$NODE kit/shotcraft/term.mjs                                  # 概览 + 新鲜度
$NODE kit/shotcraft/term.mjs --intent "逐字显现 大字入场"        # 检索

$NODE kit/shotcraft/plan.mjs --selftest                       # 11 项自检（含负控）
```

### 输入清单的两个字段（★ 别只写一个）

```jsonc
{
  "shot": 1, "dur": 1.90,
  "text": "定调 · 大字「低功耗 · AOV」逐字打出 ＋ 极平功耗曲线 ＋ 24H 环",
  "intent":     "逐字显现 大字入场 描线生长 环形进度",   // 喂**术语库**
  "cardIntent": "大字逐字入场 文字reveal 混排字重",      // 喂**镜头卡库**（可选）
  "terms": [], "card": "", "note": "只取 A 式动作段，56f 正好塞进 1.90s"
}
```

> ★ **为什么要 `cardIntent`**：两个库**语汇不同**（术语库偏"技法/实现"，镜头卡偏"整镜结构"）。
> 实测（镜1）：为修术语把「描线生长」加进 intent ⇒ 术语 top1 从 `M07`→`Kt01` ✓，
> 但镜头卡 top1 从 `type-assembly-moves` **掉成** `draw-svg-trace` ✗ —— 同一个意图喂两边会**互相打架**。
> 缺省时 `cardIntent` 回落到 `intent`（老清单不用改）。

### plan.mjs 会替你查的东西（确定性，全部可复现）

| 检查 | 拦不拦 |
|---|---|
| **幻觉 id**：`terms`/`card` 里写了库里没有的名字 | **ERR，拒出方案**（exit 1） |
| 缺 `dur` / 缺 `intent` / `shots` 为空 | **ERR** |
| **像拿文案原文当意图**（成句或 >28 字且无动效语汇） | WARN（铁律 181：实测 rel≈0.05） |
| **术语/镜头卡重复**（同一项当主项 ⇒ 全片同一手法别超 2 次） | 自检段报出 |
| **时长对账**：全片是否都短于卡片典型时长 | 自检段报出 |
| **低相关度镜**（rel < 1.2） | 只报读数 + 提示走两轮检索 |

> ⚠️ **「低相关度」≠「库里没有」** —— 它只说明**用词没对上库里的话术**。
> 修法：**两轮检索**（看 top1 的 `cn`/`desc`，把它的词抄进 intent 再跑）。
> 实测：镜1 一轮 `M07 描线生长` 4.43 / `D04 场` 4.13 咬住且排序不稳 → 聚焦成
> 「逐字显现 文字一个一个出来 错峰」⇒ `Kt01 逐字显现` **5.52** 一骑绝尘。
> 两轮后仍低 ⇒ 才**疑似**库里没这个动效。

> ★ **一镜一主动效**（`term.mjs` 会自动提示）：意图里**并列多个动效**时，2-gram 词袋会把它们
> 各命中一半 ⇒ top1/top2 咬得很近、**排序不稳**（谁第一全看用词）。
> `term.mjs` 在 `top2.rel / top1.rel > 0.85` 时会打出「排序不稳定，建议聚焦一个主术语再搜」。

## spec.json 新增字段约定（`card`）

```jsonc
{
  "shot": 2,
  "t0": 3.20, "t1": 6.10,
  "narration": "它把 CPU、内存和显示控制器，全塞进了一颗芯片里。",
  "voice_kw": "一颗芯片",
  "card": {
    "shot": "blur-slide",           // 这一镜的主/体动效卡（必须是库里的真实 id）
    "cam":  "space-camera-moves",   // 运镜卡（可选）
    "fx":   "impact-feedback",      // 寄生型技法卡挂这里（**不能**放 shot）
    "variants": { "cam": "A" },     // 多方案卡必须写变体，否则实现时不知道选哪式
    "params": { "gap": 0.035 },     // 覆盖卡片默认值（写"改了什么"）
    "why": "旁白是并列参数，需要专业但不抢戏的默认 reveal；镜长 2.9s 短于卡片 3.8s ⇒ 取入场段+减词"
  }
}
```

**全部字段可选** —— 不写不报错（老工程零迁移成本），但写了才享受校验。
`pick.mjs --from-spec` 会把没写的镜列成 TODO、把写错的（幻觉卡名 / 技法卡误用）报 ERR。

## 判据清单（谁判什么，别搞混）

| 判据 | 在哪 | 有牙吗 |
|---|---|---|
| 卡名真实存在（防 AI 幻觉编卡名） | `pick --from-spec` | ✅ 负控命中 |
| 技法卡不许当镜头主卡 | `pick --from-spec` | ✅ 负控命中 |
| P4 一手法一次主角（同卡 >1 次报警） | `pick --from-spec` | ✅ 负控命中 |
| 时长对账（实测镜长 vs 卡片典型） | `pick --from-spec` / `--intent` | ✅ 三分支 |
| 时间轴连续无缝 / 末镜对齐 dur / 首镜从 0 | `verify.mjs` | ✅ 负控命中 |
| 安全区在画幅内 | `verify.mjs` | ✅（**只判出画**，边距只报读数） |
| 审美 27 条 | `verify.mjs` 出核对表 | ❌ **必须人眼**（除标注 ✅自动 的几条） |
| 索引解析完整（157 张卡的段落齐备） | `index.mjs` | ✅ 16 项自检含 4 负控 |
| 对象类型错配（`type-*` 吸铁石卡） | `pick --intent` | ⚠️ **降权 −1.50 + 警告**（不硬拦：卡库里可能就它对口） |
| 检索质量（`rel<1.2` ⇒ 提示两轮检索 / 可能是库存缺口） | `pick --intent` | 💬 提示，不拦 |

> ★ **纪律重申**：`verify.mjs` 里区分「硬判据」与「读数」——
> 安全区边距**只报读数不判错**，因为上游 `aesthetic-rules.md` 里**没有**安全区数值规定
> （它只规定了"字幕 ≥5% 帧高"，那是**字高**不是边距）。
