# qc_l1.py —— 视频成片 L1 技术门禁

HTML 动效 → puppeteer 逐帧 → ffmpeg 合成 MP4 之后的第一道自动体检。
**硬项 FAIL 直接打回重做，不用人眼看；WARN 只提示，交二审（人眼）判断。**

---

## 1. 依赖与安装

**零依赖。** 只需要：

- Python 3.8+（只用标准库：`argparse / json / os / re / subprocess / sys / unicodedata`）
- `ffmpeg` 与 `ffprobe` 在 PATH 中（实测通过版本：8.1.2）

验证：`ffmpeg -version`、`ffprobe -version` 能出版本号即可。不需要 `pip install` 任何东西。

---

## 2. 怎么跑

```bash
python qc_l1.py <video_path> [--fps 30] [--expect 11.0] [--json out.json]
```

| 参数 | 说明 |
|---|---|
| `video_path` | 必填，成片路径（支持中文路径、空格） |
| `--fps` | 期望帧率，默认 30（产线统一 30fps，一般不改） |
| `--expect` | 期望时长（秒）。传了才判定时长；不传只报告 |
| `--json` | 结构化结果落盘路径，供流水线存档 / 看板消费 |

**退出码**（关键，流水线靠它分流）：

| 码 | 含义 |
|---|---|
| `0` | 无 FAIL（允许有 WARN / UNKNOWN / INFO）→ 流入二审 |
| `1` | 至少一个 FAIL → 打回合成环节重做 |
| `2` | 输入错误（文件不存在 / ffprobe 探测失败）→ 查路径，不是成片问题 |

流水线接法示例：

```bash
python qc_l1.py out.mp4 --expect 11.0 --json qc/out.json
if [ $? -eq 1 ]; then echo "L1 未通过，打回重做"; exit 1; fi
```

## 3. 九个检查项的阈值，以及为什么这么定

| # | 项 | 级别 | 阈值 | 依据 |
|---|---|---|---|---|
| 1 | 容器与规格 | **FAIL** | 必须 1920×1080、30fps（容差 0.01） | 产线统一交付规格；帧率不达标会导致后面拼接/推流失帧、音画不同步 |
| 2 | 时长 | FAIL（传 `--expect` 时） | 与期望差 >0.3s | 0.3s 是配音剪辑能感知的最小错位；超过说明丢帧或尾帧没收住 |
| 3 | 黑帧 | **FAIL** | >0.5s 黑帧，片头/片尾各 1s 内豁免 | 正片里 >0.5s 全黑＝渲染漏帧或转场没接上；头尾留黑常是刻意的淡入淡出，故豁免 |
| 4 | 静帧 | WARN | >0.5s 画面完全静止 | "PPT 感"嫌疑，可能是动效没跑起来或 timeline 断档；但要人眼确认是不是刻意定版，所以不拦 |
| 5 | 静音段 | INFO | 报告所有 >0.5s 静音（-30dB 门限） | 成片首尾留白、转场停顿很常见，脚本不判断意图，只把时间点列给二审 |
| 6 | 响度 | **FAIL** | I = -14 ±3 LUFS；true peak ≤ -1 dBTP | -14 LUFS 是 YouTube 归一化口径；±3 LU 是平台可接受窗口（再宽就是全片偏吵/偏轻）；true peak 卡 -1 dBTP 是给有损编码留 intersample peak 余量，避免二次编码后削顶 |
| 7 | 削波 | **FAIL** | Peak level ≥ 0 dBFS | 样本值顶到满刻度就是硬削失真，不可恢复，必须回混音端降增益重导 |
| 8 | 广播合法范围 | WARN | Y∈[16,235]、UV∈[16,240] | Rec.709 8bit 的合法取值范围；超范围在播控/广电站会被压暗或溢出 credited；网络投放多数平台会宽容处理，所以只提示 |
| 9 | 闪烁（PSE） | **FAIL** | 1s 滑动窗口内亮度翻转 ≤3 次 | Ofcom 光敏性癫痫指引：1 秒内 >3 次闪烁且亮度变化显著即不合格。这里"显著"取相对亮度变化 ≥10%（8bit 下 ΔY ≥ 25.5） |

补充说明：

- **第 9 项**按 0.1s 步长采样全片 YAVG（signalstats 原生时间轴重采样），只有"大幅且正负交替"的相邻跳变才算一次翻转，避免普通转场被误杀。
- **第 3、8、9 项共用一次解码**（signalstats 出 YAVG 序列，顺带给 YMIN/YMAX/SAT），所以 106s 成片全量体检约 35 秒。
- 每条 ffmpeg/ffprobe 命令 **超时 120s，异常不崩**；拿不到值的项标 `UNKNOWN` 并在备注写明原因，**绝不假装通过**。

## 4. 状态与二审流程怎么接

控制台先看表格，只看 `[状态]` 列：

- `FAIL` → 表格下方 "L1 GATE: FAIL (n 项)" 会逐条给出一句话原因 → **直接回合成环节**
- `WARN` → 不阻断。进二审时把这几项当"重点看"清单交给剪辑师
- `UNKNOWN` → 脚本没拿到值（超时、无音轨、解析失败）→ **必须由人补看**，不能因为没标 FAIL 就放行
- `INFO` → 纯信息

**二审（人眼）分工建议：脚本管"能不能交付"，人管"好不好看"。** L1 只卡技术硬伤（响度、削波、黑帧、闪烁、规格），不评价构图、节奏、配色、动效质感。

推荐流程：

```
合成完毕 → qc_l1.py → 退出码 0 ? → 二审清单 = WARN 项 + UNKNOWN 项 + 主观项
                    ↘ 退出码 1  → 打回重做，重跑 L1
```

`--json` 落盘的结构可直接喂给看板/归档：

```json
{ "file": "...", "meta": {...},
  "checks": [{"name","status","value","threshold","detail"}, ...],
  "gate": "FAIL", "fail_count": 1, "warn_count": 2, "unknown_count": 0 }
```

## 5. 已知容易踩的点

- **Windows 控制台编码**：脚本已强制 stdout/stderr 走 UTF-8（`errors=replace`），中文路径和中文表格不会炸。
- **中文路径**：全部走 `subprocess` 列表参数，不做 shell 拼接，无注入/转义问题。
- **音频判定依赖 ebur128 的 `peak=true`**：不加这个开关 ffmpeg 不输出 True peak 段，第 6 项的一半会掉成 `UNKNOWN`。脚本里已经写死。
- **freezedetect / blackdetect 的输出格式不稳定**：同一版本 ffmpeg 也可能"单行三条"或"逐行三条"，脚本的 `parse_segments()` 两种都兼容。

## 3D 项目的额外门禁（2026-09-10）

L1 是**成片级**检查（规格/黑帧/响度/闪烁），覆盖不到 3D 摄影机的**轨道级**问题。
走 `--mode 3d` 的工程**必须额外手动跑** `语音转动画-审计loop.md` **§5 3D 摄影机专项门禁**：

| 校验 | 方法 | 阈值 |
|---|---|---|
| `dist_min`（摄影机→POI 全程最小距离） | 采样 `CAMTRACK` 算 `hypot(cam-poi)` | **≥ 200**，否则穿模/透视炸裂（BUG-2009/2010） |
| `roll` 归零 | 列出所有 `\|roll\|>0.01` 的关键帧 | 非 `dutchTilt` 段必须全 0（BUG-2008） |
| 关键帧 NaN | 生成器已逐字段查，跑通即通过 | 出现非数值直接 die（BUG-2002） |

> 生成器 `new_project.js` 已内置两条守卫：`dutchTilt` 后无 `level` → die；关键帧非数值 → die。
> 但 `dist_min` 需要自己采样算，**它是唯一没被自动化的 3D 硬门禁**。
